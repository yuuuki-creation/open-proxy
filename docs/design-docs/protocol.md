# 主控与 Agent 通信协议

- 状态：已采纳（2026-09-23，定义在 `protocol/openproxy/agent/v1/`）
- 创建：2026-09-23
- 最后更新：2026-09-23

> **摘要**：WebSocket 二进制帧，每帧一条 Protocol Buffers 消息。两个方向各一个外壳（`AgentMessage`、`MasterMessage`），带消息 ID 和「回复哪一条」。连接后 Agent 先发 Hello；版本一致才同步期望状态，不一致时只收发几条「稳定消息」（Hello、升级、流量上报、卸载）。期望状态整份下发、逐项应用，节点按 ID 引用用户；自签证书也由主控生成下发。删除服务器时 Agent 自动卸载。字段以 `protocol/` 里的定义为准，本文只写结构和规则。

连接参数（WSS、Token 放第一条消息、心跳 30 秒、离线 90 秒、重连退避、拒绝重复连接）已在 [architecture.md](architecture.md) 的「主控与 Agent 通信」定下，这里不重复。参考了妙妙屋 X 的通信笔记，只借思路。

## 传输与外壳

- 地址：主控 HTTPS 端口上的 `/api/agent/ws`；Agent 不监听任何端口
- 编码：WebSocket 二进制帧，一帧一条消息，单帧上限 4 MiB；调试日志把消息转成 JSON 打印
- 外壳：Agent 发的是 `AgentMessage`，主控发的是 `MasterMessage`，结构相同：
  - `id`：发送方自增的消息 ID，从 1 开始；两个方向各自计数
  - `reply_to`：这是回复时，填对方那条请求的 `id`；不是回复就填 0
  - `body`：`oneof`，具体消息
- 三类消息：
  - **请求**：对方必须回复；发送方挂一个等待表并设超时，超时后到的回复直接丢弃
  - **回复**：`reply_to` 指向请求
  - **推送**：单向，不回复、不重发
- 收到不认识的消息（通常是对方版本更新，解析后 `body` 为空）：一律忽略。接收方分不清它是请求还是推送，所以请求方靠超时发现对方不支持
- `ErrorReply` 的「不支持」用于认识、但当前不能处理的请求，例如版本不一致时收到非稳定的请求

## 消息一览

A = Agent，M = 主控。「稳定」的含义见「兼容规则」。

| 方向 | 消息 | 类型 | 内容 | 稳定 |
| --- | --- | --- | --- | --- |
| A→M | `Hello` | 请求，连接后第一条 | Token、Agent 版本、架构、实例 ID、已应用的状态版本、上次升级是否回滚 | ✅ |
| M→A | `HelloResult` | 回复 | 结果（成功 / Token 无效 / 重复连接 / 服务器已删除）、主控版本、是否同步 | ✅ |
| M→A | `DesiredState` | 推送 | 整份期望状态，见「期望状态」 | |
| A→M | `StateReport` | 推送 | 已应用的状态版本、失败项 | |
| A→M | `TrafficReport` | 推送，每 10 秒 | 实例 ID；按「节点 × 用户」的累计上下行；网卡累计收发；`boot_id` | ✅ |
| M→A | `Upgrade` | 请求，超时 5 分钟 | 目标版本、下载路径、SHA-256、签名 | ✅ |
| A→M | `UpgradeResult` | 回复 | 下载、验签、替换是否成功 | ✅ |
| M→A | `Uninstall` | 请求，超时 1 分钟 | 删除服务器时让 Agent 卸载自己 | ✅ |
| A→M | `UninstallResult` | 回复 | 是否开始卸载 | ✅ |
| M→A | `CheckRealityTargets` | 请求，超时 1 分钟 | 候选伪装目标列表 | |
| A→M | `CheckRealityTargetsResult` | 回复 | 每个目标：是否 TLS 1.3、是否 H2、延迟、证书是否有效、错误 | |
| M→A | `ScanRealityTargets` | 请求，超时 20 分钟 | 网段、并发数、速率 | |
| A→M | `ScanRealityTargetsResult` | 回复 | 扫描结束时一次性返回候选列表 | |
| 双向 | `ErrorReply` | 回复 | 原因（不支持 / 处理失败）、说明 | ✅ |

## 连接流程

1. Agent 连上 WSS，发 `Hello`
2. 主控校验 Token（比对哈希）和重复连接，回 `HelloResult`：
   - Token 无效、重复连接：主控关闭连接，Agent 退避后重试（Token 无效用长退避）
   - 服务器已删除：Agent 执行卸载，见「删除服务器」
   - 成功且版本一致：「同步」为是。主控比较 `Hello` 里的状态版本和当前版本，**不相等**就推送 `DesiredState`（用不相等而不是「更小」，数据库从备份恢复后也能追平）
   - 成功但版本不一致：「同步」为否。Agent 按本地状态继续服务，只收发稳定消息；主控不推 `DesiredState`，等管理员点「升级」
3. 之后 Agent 每 10 秒发 `TrafficReport`；每应用完一份状态发一次 `StateReport`
4. 主控每 30 秒发 WebSocket ping（在协议层之下，不是消息）

## 期望状态

一台服务器一份，整份下发。组成：

| 部分 | 内容 |
| --- | --- |
| 版本 | 单调递增。取「上一个版本 + 1」和当前毫秒时间戳中的大者，数据库从备份恢复后也不会倒退 |
| 用户 | 这台服务器上用得到的用户：ID、UUID（VLESS）、密码（Hysteria2、AnyTLS、Mieru）、Shadowsocks 2022 用户密钥 |
| 节点 | ID、端口、用户 ID 列表、落地出口 ID（0 表示直连）、协议参数（五选一）：VLESS + REALITY（私钥、short ID、伪装目标）；Hysteria2（混淆密码、端口跳跃范围）；AnyTLS；Shadowsocks 2022（加密方式、服务端主密钥）；Mieru |
| 落地出口 | ID、地址、端口、账号、密码（SOCKS5） |
| 自建落地 | 这台服务器当落地机时的 SOCKS5 入站：端口、账号、密码、允许的来源 IP（主控生成状态时把服务器地址解析成 IP） |
| 证书 | 这台服务器上 TLS 节点共用的证书和私钥（PEM）：有域名的是主控申请的正式证书，没有域名的是**主控生成的自签证书**。主控记下自签证书的 SHA-256，订阅里写成固定指纹；重装 Agent、换机器后指纹不变 |

- 命名：入站 tag 用 `node-<节点 ID>`，出站 tag 用 `exit-<出口 ID>`；sing-box 和 Mieru 里的用户名用用户 ID。流量上报直接按这两个 ID 归属，主控不用再查表
- 下发节奏：主控在变更后等 3 秒再推送，把连续的变更合并成一次（Hysteria2 每次加人都会断会话，见 architecture.md「用户变更」）；Agent 正在应用时又收到新状态，应用完只处理最新的一份
- 本地保存：Agent 把最近一次收到的 `DesiredState` 原样（protobuf 编码）写到磁盘，原子写入后立即读回校验；启动时先按它启动

## 应用规则

- **逐项应用**：节点、出口、自建落地、证书、端口跳跃各自独立应用。某一项失败（例如端口被占用），这一项保持原样，其他项照常生效；失败项写进 `StateReport`，面板上提示
- 应用前用 sing-box 的配置解析校验每一项，校验不过的按失败处理
- `StateReport` 里的「已应用的版本」表示这一版已经处理完（含失败项），不表示全部成功
- **停用即时生效**：追踪层只放行「这个节点的用户列表里有的用户」，按新状态立即更新。用户从节点上移除后，追踪层马上断开并拒绝他，不管这个节点的入站重建有没有成功。所以主控判断「停用已生效」只看已应用的版本，不受失败项影响

## 上报

- `TrafficReport`：
  - 按「节点 × 用户」的累计值，只发非零的行；Agent 进程重启后从零开始，主控靠实例 ID 识别
  - 网卡：默认路由所在网卡的累计收发字节和 `boot_id`。主控用相邻两次的差算网速（面板显示 10 秒平均值）和整机流量
  - 升级、卸载前补发一次；进程崩溃时最多丢最后 10 秒的流量
- `StateReport`：每应用完一份状态发一次，连接成功、同步开始时也发一次。失败项写明是哪一项（节点、出口、自建落地、证书、端口跳跃 + ID）和原因

## 升级

1. 管理员点「升级」，主控按 `Hello` 里的架构发 `Upgrade`：目标版本、下载路径、SHA-256、签名
2. Agent 用自己配置的主控地址拼出完整 URL 下载（Token 放请求头；只给路径不给完整 URL，Token 就不会发到别的地方），校验 SHA-256，用内置公钥验签；写到旁边的临时文件，备份旧版本，原子替换，回 `UpgradeResult`
3. Agent 补发一次 `TrafficReport` 后退出，由 systemd 拉起新版本
4. 新版本几分钟内连不上主控或认证失败，就换回备份并重启；下次 `Hello` 里带上「上次升级回滚了」，面板显示

## 删除服务器

- 管理员删除服务器时，主控发 `Uninstall`。Agent 回复后补发一次 `TrafficReport`，然后停掉所有入站、清理 nftables 规则、删除自己的文件和 systemd 服务
- 删除时不在线的：主控保留已删除服务器的 Token 哈希。它下次连上来，`HelloResult` 回「服务器已删除」，Agent 同样卸载
- 只有「服务器已删除」才卸载。Token 无效（例如主控从旧备份恢复、查不到这台服务器）只退避重试，不卸载，免得主控出错时把节点全部删掉

## REALITY 目标检测与扫描

- 检测：管理员选中的目标由 Agent 在服务器上访问几次，回报 TLS 1.3、H2、延迟、证书是否有效；主控据此决定能不能保存（[nodes.md](nodes.md)「REALITY 伪装目标」）
- 扫描：慢速、低并发扫描主控指定的网段（通常是服务器所在的 /24），结束时一次性回报候选。第一版不做进度推送；连接断开就算失败，重新发起

## 兼容规则

- 主控和 Agent 版本一致时，双方用同一份 `protocol/` 编译，所有消息都能用
- 版本不一致时只用**稳定消息**（上表打 ✅ 的，加上两个外壳）。稳定消息必须让新旧版本互相听懂：字段只加不改，不改含义
- 所有消息都遵守线上兼容：不改字段编号和类型，删字段时保留编号（`reserved`）。在指向 main 的 PR 上用 `buf breaking` 自动检查
- `TrafficReport` 算稳定消息，是为了主控升级后、Agent 还没升级的这段时间里流量照常统计；否则 Agent 升级重启时，这段时间的流量全部丢失。这段时间里超额停用暂停，Agent 升级后恢复
