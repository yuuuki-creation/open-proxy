# 系统架构

- 状态：草稿（讨论中）
- 创建：2026-09-17
- 最后更新：2026-09-27

> **摘要**：主控（Rust）+ Agent（Go，内嵌 sing-box 和 Mieru）。Agent 主动连主控 WSS；主控下发带版本号的全量期望状态（入站、用户、出口、证书），Agent 自己比对差异后应用；Agent 上报累计流量 + 实例 ID，主控算增量。按用户统计和断开连接挂在 sing-box 的 ConnectionTracker 上。Agent 二进制由主控托管，主控和 Agent 同版本，一键升级，签名 + 自动回滚。末尾有「要避免的坑」和决策记录。

范围和核心选型见 [product-scope.md](product-scope.md)。参考了妙妙屋 X 源码笔记：数据模型、通信协议、Agent 内部。

## 组件

```
 管理员浏览器 ──HTTPS──┐                        ┌──HTTPS── 朋友的客户端（拉订阅）
                      ▼                        ▼
 ┌─────────────────────────── 主控（一个进程）───────────────────────────┐
 │  React 面板    REST API    订阅服务    定时任务（超额 / 到期 / 重置）    │
 │  Agent 网关（WebSocket）    Agent 二进制托管    SQLite                  │
 └────────────────────────────────▲──────────────────────────────────────┘
                                  │ WSS，由 Agent 主动连接，每台服务器独立 Token
              ┌───────────────────┴────────────────────┐
      节点服务器上的 Agent                        落地机上的 Agent
      ├ sing-box（VLESS / Hy2 / AnyTLS / SS2022）    └ SOCKS5 入站（只放行自己的服务器）
      ├ Mieru
      ├ 连接追踪层：按用户统计流量、断开连接（将来限速也加在这里）
      └ 本地保存最近一次收到的期望状态
```

### 语言选型（2026-09-17）

- 主控后端最初定 Go（和 Agent 共用代码），讨论后改为 Rust
- 讨论过 Agent 也用 Rust，放弃的原因：
  - Rust 里协议最全的是 [shoes](https://github.com/cfal/shoes)（MIT，v0.2.8）：我们要的协议里除 Mieru 都支持，也能当库用；但 VLESS、Hysteria2、Shadowsocks 2022 每个入站只能配一个用户（只有 AnyTLS 支持多用户），没有按用户统计和运行时增删用户的接口，基本一人维护，依赖版本全写 `*`
  - Mieru 的 Rust 实现只有个位数 star 的个人项目，大多没有许可证
  - 其他做法的代价：Rust Agent 另起 Go 内核进程（两个进程 + 本机通信）；控制外部 sing-box 进程（增删用户要重启内核，所有人断线）；基于 shoes 自己改造加自写 Mieru（工作量最大，抗封锁实现不成熟）

## 主控与 Agent 通信

### 连接

- Agent 主动连接主控 HTTPS 端口上的 WebSocket；主控必须有域名和正规证书，加密直接依赖 TLS，不另做加密层
- Agent 不监听任何管理端口
- 消息定义、连接流程、兼容规则见 [protocol.md](protocol.md)；代码由 `protocol/` 里的 Protocol Buffers 定义生成
- 认证：Token 放在 WebSocket 的第一条消息里，不放 URL，避免进反向代理日志
- 同一个 Token 已有连接在线时，拒绝新连接，不互相踢
- 主控每 30 秒发一次 ping，90 秒没有响应判定离线；每个连接的写操作串行化，并设 10 秒超时
- 断线重连退避：5 秒逐步拉长到 5 分钟；认证失败用更长的退避

### 配置同步：全量期望状态

- 主控为每台服务器生成一份完整的期望状态：有哪些入站、每个入站有哪些用户、流量走哪个出口、TLS 入站用的证书和私钥；每份带单调递增的版本号
- 用户、套餐、节点、出口发生相关变更时，重新生成受影响服务器的期望状态并推送
- Agent 对比本地当前状态，只应用差异，然后回报「已应用的版本号」和失败项
- Agent 连接时上报当前版本，和主控不一致就推送最新状态。离线期间的变更靠这一步自动追平，不需要额外的对账任务
- Agent 把最近一次期望状态保存在本地磁盘：Agent 重启时先按本地状态启动，主控不可达也能继续服务

### 流量上报

- Agent 上报每个「用户 × 入站」的累计上行 / 下行，附带实例 ID（Agent 每次启动随机生成）
- 主控记住上次收到的原始值来算增量；实例 ID 变了说明 Agent 重启过，此时增量 = 新值；第一次见到的计数也按增量算，因为 Agent 的计数从零开始（见 [database.md](database.md)「流量怎么算」）
- 上报周期 10 秒

## 用户凭据

- 每个用户一套凭据，所有节点通用：VLESS 用 UUID；Hysteria2、AnyTLS、Mieru 用密码；Shadowsocks 2022 用长度符合加密方式的用户密钥
- 按节点统计流量靠 Agent 知道连接进了哪个入站，不需要为每个节点区分凭据
- 重置凭据时一次换掉全部，并推送到所有相关服务器

## Agent 内部

### 组成

- 一个 sing-box 实例：用户入站（VLESS + REALITY、Hysteria2、AnyTLS、Shadowsocks 2022）；落地机上的 SOCKS5 入站；落地出口用的 SOCKS5 出站
- 每个 Mieru 节点一个 mieru 多路复用器（mieru 的 `pkg/protocol` 里的 mux，不用给第三方集成的 `apis/server`，理由见「用户变更」）：Agent 接受连接、回 socks5 应答后，带上节点 tag 和用户交给 sing-box 路由（`Router.RouteConnectionEx`、`RoutePacketConnectionEx`），统计、断连、落地出口都和其他协议走同一条路
- 连接追踪层：实现 sing-box 的 `ConnectionTracker`，通过 `Router.AppendTracker` 注册。sing-box 在选定出站之后、拨号之前调用它，参数里带入站 tag 和用户，可以替换成包装过的连接。不需要 fork sing-box
- 状态管理：一把锁串行化所有变更，重建入站的整个过程都在锁里；持有当前生效的期望状态

### 按用户统计

- 追踪层给每条连接包一层计数，计数器按「用户 × 入站」放在 Agent 里，不放在 sing-box 实例里，所以入站或实例重建时不归零；只有 Agent 进程重启才归零（靠实例 ID 识别）
- Mieru 的连接交给 sing-box 路由后，同样经过追踪层

### 停用用户时断开存量连接

- 追踪层按用户登记每条连接的关闭函数，连接结束时注销
- 停用或删除用户：追踪层立即关闭他所有的存量连接，并拒绝他的新连接；从入站配置里移除可以晚一点，按「用户变更」的做法合并进下一次重建
- 只从入站移除是不够的：TCP 类协议重建入站不影响已建立的连接，被移除的人自己的也一样，超额用户的长连接还能继续用
- 「检查是否已停用」和「登记连接」要在同一把锁里，否则恰好在停用那一刻建立的连接会漏断
- 第一版就要做

### 用户变更（2026-09-18 原型实测）

做法：用 sing-box 的 `InboundManager` 按同一个 tag `Remove` 再 `Create` 重建入站，耗时约 1 毫秒。实测结果：

| 协议 | 重建入站的影响 | 做法 |
| --- | --- | --- |
| VLESS + REALITY、AnyTLS、Shadowsocks 2022 | 无影响，其他用户的在传连接一秒不停 | 随时重建 |
| Shadowsocks 2022 | 另有 `ManagedSSMServer.UpdateUsers`，0 毫秒热更新，不用重建 | 优先走热更新 |
| Hysteria2（QUIC） | **该入站上全部在传会话立刻中断**，不会自动续上；新连接立即可用 | 见下面的规避 |

Hysteria2 的规避办法：

- 短时间内的多次用户变更合并成一次重建（下发端做防抖）
- 停用用户（超额、到期）不靠重建：追踪层直接断开该用户的连接并拒绝新连接，效果即时且不影响他人；入站配置里的清理可以延后到下一次合并重建
- 新增用户必须重建才能放行，所以「加人」是唯一会打断 Hysteria2 的操作，尽量攒批

注意事项：

- Shadowsocks 入站不要开 `managed` 选项：那会禁止配置里写静态用户列表，而不开也能调 `UpdateUsers`
- 启动实例前要自己准备好 context：`box.New` 会把服务注册进 context 里的服务注册表（存在则复用），必须先建好注册表和 pause 管理器再传进去，否则运行时调用 `InboundManager.Create` 会空指针崩溃
- Mieru（2026-09-27 实测，agent 分支 R20260927-agent-01、02）：`apis/server` 改用户只能停掉实例再建新的，而它的 `Stop()` 会关掉所有底层连接（注释说不断开，实际会断），节点上所有人都会断线。所以直接用 mux：只增删用户时在运行中换用户列表，已有连接不断，被删用户的连接由追踪层立即断开；有用户改了密码时重建实例，因为用旧密码建立的底层连接还能继续开新会话，只有全部关掉才能让旧密码立即失效

### 落地出口

- 节点级：一个入站固定走一个出口
- sing-box 的路由规则不能在运行时修改，而节点和出口会随时增删，所以不写按入站分流的路由规则。路由的默认出站是 Agent 自己注册的「分发」出站：拨号时从连接上下文里取入站 tag，查 Agent 内存里的「节点 → 出口」对应表，交给 `exit-<ID>` 或直连出站。对应表随期望状态更新，不用重建 sing-box 实例（2026-09-23 改，原来写的是每个入站一条路由规则）
- 换落地：按同一个 tag 重建 `exit-<ID>` 出站
- 自建落地机：SOCKS5 入站要求账号密码；来源 IP 也在分发出站里检查，只放行期望状态里列出的 IP
- 分发出站已验证可用（R20260927-panel-01）；同 tag 替换出站后新连接是否立即走新出站还没验证，见「未验证的假设」

### 不能访问服务器本机和内网（2026-09-27 定）

测试时发现经节点能连到服务器本机的 127.0.0.1（agent 分支技术债 agent-5）：朋友能借节点访问服务器上只对本机开放的服务、内网里的其他机器。做法：

- 在分发出站拨号前检查目标，所有协议（包括 Mieru）、TCP 和 UDP 都经过这里
- 不允许的地址：回环、私有（RFC 1918、`fc00::/7`）、链路本地、未指定（含 `0.0.0.0/8`）、组播、广播 `255.255.255.255`、`100.64.0.0/10`，以及本机网卡上的任何地址（缓存 1 分钟）；IPv4 映射的 IPv6 地址先还原再判断
- 目标是 IP：不允许就拒绝。目标是域名且走直连：先解析，去掉不允许的地址，全不允许就拒绝，用剩下的地址拨号，不再解析第二次（防 DNS rebinding）
- UDP 每个包都检查：发往不允许地址的包丢掉，会话继续；第一个包就不允许时整个会话按失败处理
- 走落地出口：只检查 IP 目标，域名由落地解析，管不到。Agent 自己连落地服务器不受限制（落地可以在本机）
- 面板和期望状态里没有开关。只有测试用的命令行参数 `-allow-private-targets` 能关掉检查，开了会在启动时打警告：测试 VPS 上所有地址都是本机地址，本机上的端到端测试要靠它（安装脚本经 `OP_AGENT_ARGS` 传）

### 将来的限速（第一版只留位置）

- 挂在同一个追踪层的连接包装里；第一版包装里只有计数
- 原本担心 sing 库的拷贝路径会剥掉包装、直接 splice 绕过限速。2026-09-18 实测：这套配置下**根本不发生 splice**（REALITY 的外层 TLS 由服务端终结，服务端拿到的不是裸 TCP 连接），统计也因此不会被绕过。加限速时仍要复查这一点

### 应用配置

- 应用前用 sing-box 的配置解析做校验
- 逐项应用：某一项失败时这一项保持原样，其他项照常生效，失败项上报给主控（见 [protocol.md](protocol.md)「应用规则」）
- 本地状态文件原子写入，写完立即读回校验

### 服务器网卡流量

- 读 `/proc/net/dev`；判断服务器是否重启用 `/proc/sys/kernel/random/boot_id`，不用 Agent 启动时间

## 未验证的假设

| 假设 | 依赖它的设计 | 结果 |
| --- | --- | --- |
| Mieru 服务端库支持多用户，连接上带用户身份，能按用户统计 | Mieru 入站、按用户统计 | 成立：mux 支持多用户，流量按「节点 × 用户」上报（R20260927-agent-01、02） |
| Mieru `Stop()` 后新实例能立即接管同一端口，旧连接继续传输 | Mieru 的用户变更 | **不成立**：`Stop()` 会断开所有连接。改用 mux 在运行中换用户列表，见「用户变更」 |

## 流量、超额与到期

- 存储：每个用户的全部累计和本周期起点，加上按天累加的日账本。重置只记录新周期起点，不删数据
- 停用原因由规则算出（手动 > 到期 > 超额），不存「停用已生效」；面板按服务器的同步情况显示是否生效。表结构和规则见 [database.md](database.md)
- 停用时保留凭据，恢复时用原凭据，订阅链接不变
- 检查时机：收到流量上报时检查涉及的用户是否超额；到期和每月重置每分钟检查一次；统一使用管理员设置的时区
- 主控离线期间，Agent 按本地状态照常服务，但不会执行超额停用

## 监控

- 面板显示每台服务器：在线 / 离线、Agent 版本、实时上下行速度
- 服务器整机流量：读网卡。每台服务器可以设月额度和重置日（对应 VPS 账单日），面板显示用量进度。只做显示，不自动停止服务

## 发布、安装与升级

- **分发**：主控发布包内置 amd64 / arm64 两个 Agent 二进制，安装和升级都从主控下载；源码仓库保持私有
- **版本**：主控和 Agent 同版本才同步配置。版本不一致时，Agent 按本地状态继续服务、暂停同步；主控升级后在面板点「全部升级」。版本上报和升级指令这两类消息必须跨版本保持不变，否则旧 Agent 无法被升级
- **签名**：发布时用离线私钥给 Agent 二进制签名，Agent 内置公钥，由正在运行的旧版本验证新版本。主控被入侵也推送不了恶意程序
- **替换与回滚**：新二进制先写到旁边再原子替换；保留旧版本备份；新版本启动后几分钟内连不上主控，自动换回备份（靠下面的升级标记文件）
- **安装**：面板生成一行安装命令（主控地址 + Token），脚本检测架构、写配置、注册 systemd 服务
- **Agent 的文件**（2026-09-23 定）：

  | 路径 | 内容 |
  | --- | --- |
  | `/usr/local/bin/op-agent`、`op-agent.bak` | 二进制和升级前的备份 |
  | `/etc/op-agent/op-agent.conf` | 安装脚本写的配置，每行一个 `KEY=value`：`MASTER_URL`、`TOKEN`；权限 0600。Agent 只读不写，所以不会写出自己读不回来的值。`MASTER_URL` 只接受 `https://`，只有本机回环地址可以用 `http://`（主控和 Agent 装在同一台机器上测试时用） |
  | `/var/lib/op-agent/state.pb` | 最近一次期望状态（protobuf 编码） |
  | `/var/lib/op-agent/upgrade.json` | 升级标记：从哪个版本升到哪个版本、开始时间。新版本认证成功后删掉；超时还在就换回备份，下次 `Hello` 里报「上次升级回滚了」 |
  | `/etc/systemd/system/op-agent.service` | systemd 服务，`Restart=always` |
  | nftables 表 `inet op_agent` | Hysteria2 端口跳跃规则 |
- **打包**（2026-09-27 定）：panel 的提交打标签 `v<版本>`，agent 的提交打 `agent-v<版本>`。panel 分支的发布工作流在 `v*` 标签上触发：检出同版本的 agent 标签，编译两种架构的 Agent（注入版本号和签名公钥），用 GitHub Secrets 里的私钥签名（`master/scripts/sign-agent.sh`），放进 `master/agent-dist/` 嵌入主控；再编译前端和主控（两种架构，静态链接），发布到仓库的 Release，并推 Docker 镜像。也可以用 `--agent-dir` 从目录读 Agent 二进制
- **Token**：主控只存哈希；安装命令只在创建服务器时显示一次；重新生成安装命令时旧 Token 失效
- **删除服务器**：Agent 自动卸载；删除后主控保留 Token 哈希，用来通知当时不在线的 Agent（见 [protocol.md](protocol.md)「删除服务器」）
- **节点地址**：由管理员填写，不用连接来源 IP

## 数据库

- SQLite，带版本号的迁移脚本；表结构见 [database.md](database.md)，接口见 [api.md](api.md)
- 表之间用数字 ID 关联（不学妙妙屋 X 用服务器名、用户名当关联键）
- 写流量用短事务，定期做 WAL checkpoint

## 要避免的坑

来自妙妙屋 X 代码注释里记录的线上事故：

| 事故 | 我们的做法 |
| --- | --- |
| WebSocket 并发写导致 panic | 每个连接的写操作串行化 |
| 写操作不设超时，发送缓冲满时卡死约 15 分钟 | 所有网络写操作设超时 |
| 同一个 Token 在多台机器上互相踢，占满 SQLite 写连接，其他服务器被误判离线 | 拒绝重复连接 |
| 双栈机器默认用 IPv6 连接，来源 IP 不可靠 | 节点地址由管理员填写 |
| Cloudflare 等中间代理掐掉空闲连接 | 主控主动发 ping |
| 快速重启时，旧连接的清理晚于新连接的认证，刚上线的服务器被标成离线 | 清理前确认连接表里登记的还是这条连接 |
| Agent 写出自己读不回来的配置值，systemd 无限重启 | 本地状态用同一套代码序列化和解析，写完立即读回校验 |
| 采集时的长读事务把 SQLite WAL 撑到 53 GiB | 短事务，定期 checkpoint |
| 用午夜快照相减算日流量，遇到重置、重启出现负数 | 只用日账本 |
| 删除用户不会断开他已有的连接 | 停用时主动关闭存量连接 |
