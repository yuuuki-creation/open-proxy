# 节点与入站配置

- 状态：草稿（讨论中）
- 创建：2026-09-17
- 最后更新：2026-09-23

范围见 [product-scope.md](product-scope.md)，架构见 [architecture.md](architecture.md)，订阅里各协议的写法见 [subscription.md](subscription.md)。

## 节点模型

- 一个节点 = 一台服务器上的一个入站：协议 + 端口 + 协议参数 + 可选的落地出口
- 一台服务器可以有多个节点
- 节点地址默认用服务器上管理员填写的地址，节点可以单独覆盖
- **只支持 IPv4**：节点地址必须是 IPv4，或解析到 IPv4 的域名；订阅里不出 IPv6 节点；只有 IPv6 的服务器不支持

## 端口

- 创建节点时自动分配：在端口范围内随机选，避开这台服务器上其他节点已用的端口和 Hysteria2 端口跳跃占用的范围；可以手动改（例如改成 443）
- 端口范围每台服务器可以设置，默认 10000–60000
- Agent 应用配置时如果端口被其他程序占用，回报失败，面板上提示

## 证书

需要 TLS 的节点（Hysteria2、AnyTLS）按服务器选择证书方式：

- **自动申请**（服务器要有域名）：
  - 主控统一申请和续期，用 DNS 验证；第一版只支持 Cloudflare（API Token）
  - 证书和私钥随期望状态下发给 Agent；DNS API 凭据只存在主控，节点服务器被入侵也拿不到
  - 到期前 30 天续期，续期后推送新版本期望状态
- **自签证书**（没有域名）：主控生成，随期望状态下发；主控记下 SHA-256 指纹，订阅里写成固定证书指纹。重装 Agent、换机器后指纹不变
- 主控自己的 HTTPS 证书也用同一套 DNS 验证申请

## Hysteria2 端口跳跃与混淆

两者都是节点上的开关，默认关闭：

- **端口跳跃**：
  - 管理员设一段 UDP 端口范围，Agent 用 nftables（没有时用 iptables）把这段端口转发到 Hysteria2 的实际端口
  - 规则带专属标记；Agent 启动时和每次应用配置时幂等重建，删除节点时清理
  - 订阅里各格式写端口范围（字段名见参考笔记，Stash 等客户端的支持情况待核实）
- **salamander 混淆**：开启后 Surge 看不到这个节点（Quantumult X 本来就不支持 Hysteria2），面板上提示

## REALITY 伪装目标

- 基本要求：支持 TLS 1.3 和 H2，从节点服务器访问延迟低，最好和服务器在同一网段或同一 AS
- 参考工具：XTLS 官方的 [RealiTLScanner](https://github.com/XTLS/RealiTLScanner)（MPL-2.0，Go），扫描指定 IP / 网段，找出合格的网站。它的 README 提醒：在云服务器上扫描可能导致 VPS 被标记
- 找候选目标，两种方式：
  - **本地扫描后导入**（默认）：管理员在自己电脑上跑 RealiTLScanner 扫节点服务器所在网段，把结果粘贴进面板
  - **面板里让 Agent 扫描**：Agent 在服务器上慢速、低并发地扫所在的 /24 网段；执行前在面板上提示被服务商标记的风险，需要确认
- **检测**：管理员选中的目标，由 Agent 在服务器上检测是否支持 TLS 1.3 / H2、延迟多少、证书是否有效。这只是几次正常的 HTTPS 访问，不算扫描；检测通过才能保存
