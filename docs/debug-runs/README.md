# 调试记录

每一轮调试写一条记录：这一轮要回答什么问题、怎么做的、结果和结论。ExecPlan 的「进度」和开发轮次记录（[dev-rounds](../dev-rounds/README.md)）里链接到对应记录。

本文件是规则，属于 main 分支。记录按分支放在子目录里：`main/`、`panel/`、`agent/`，每个子目录有自己的 `index.md`，只在对应分支上修改（见 [git-workflow.md](../git-workflow.md)）。

## 规则

- **编号**：run-id 为 `R<年月日>-<分支>-<两位序号>`，例如 `R20260918-agent-01`；同一分支同一天从 01 开始。VPS 上的工作目录同名
- **文件**：`docs/debug-runs/<分支>/<run-id>-<简短英文标识>.md`；索引是 `docs/debug-runs/<分支>/index.md`
- **时机**：开始前先写「目的」和「做法」，跑完立即补「结果」和「结论」，不要事后凭记忆补；写完推送
- **失败也要记**：失败本身就是结论
- **摘要**：标题下第一段是 1–3 行的摘要（问题 + 结论），只读摘要就能知道结论
- **篇幅**：单篇不超过 80 行。日志只贴关键片段（20 行以内）；完整日志留在测试 VPS 的 `/opt/open-proxy/runs/<run-id>/`
- **数据**：测量结果用表格，写清单位
- **脚本进仓库**：测试脚本和配置模板提交到仓库（原型放 `prototypes/<名称>/scripts/`，正式代码放各自的测试目录），记录里写路径和提交号。VPS 的 run 目录只放运行时的输出，超过 30 天会被清理
- **索引**：写完记录后更新本分支的索引


## 索引格式

````markdown
# <分支> 分支的调试记录

| run-id | 日期 | 目的 | 状态 | 结论 |
| --- | --- | --- | --- | --- |
````

## 归档

- 每个索引只保留最近 30 条
- 更早的记录移到 `<分支>/archive/<年-月>/`，并在 `<分支>/archive/<年-月>.md` 写一篇不超过 30 行的当月总结；索引末尾链接到各月总结
