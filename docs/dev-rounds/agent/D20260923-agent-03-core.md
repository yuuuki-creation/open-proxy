## 目的

让 Agent 按主控下发的期望状态运行 sing-box：建节点入站和落地出口，只放行节点上的用户，停用即时断流；应用结果上报主控；重启后先按本地保存的状态跑起来。

## 做了什么

- `agent/internal/tracker/`：实现 sing-box 的 `ConnectionTracker`，按「入站 × 用户」计累计流量；按节点放行名单，名单变化立即断开被移除的用户；「检查放行」和「登记连接」放进同一把锁，修掉原型的竞态
- `agent/internal/core/core.go`：按原型的做法启动 sing-box（`box.New` 之前先建服务注册表和 pause 管理器，`Start` 之前挂追踪层）；按 tag 建、换、删入站和出站；Shadowsocks 热更新用户
- `agent/internal/core/dispatch.go`：分发出站，按入站 tag 查「节点 → 出口」表；自建落地的来源 IP 也在这里检查
- `agent/internal/core/options.go`：期望状态转成 sing-box 选项：VLESS REALITY、Hysteria2、AnyTLS、Shadowsocks 2022 入站，SOCKS5 落地出口，自建落地入站；Mieru 节点先报失败（M5 实现）
- `agent/internal/state/`：一个 goroutine 顺序处理期望状态，排队的只留最新一份；先存盘（原子写入、读回校验），再逐项应用：放行名单 → 出口 → 节点 → 删除不用的出口 → 自建落地；按配置指纹判断要不要重建；失败项写进 `StateReport`
- `agent/cmd/op-agent/`：新增 `-data-dir` 参数（默认 `/var/lib/op-agent`，状态文件 `state.pb`）；启动时先按本地保存的期望状态跑起来，再连主控；`DesiredState` 交给状态管理；`StateReport` 没连上时记下，连上后补发
