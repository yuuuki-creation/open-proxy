## 目的

搞清楚主控下发用户变更时，Agent 重建入站会不会打断该入站上其他人正在进行的连接。

## 做了什么

- `server.go`：拆出 `inboundSpecs`，新增 `Manager` 持有实例和用户列表，提供 `AddUser` / `RemoveUser` / `RebuildTags` / `UpdateSSUsers`；`tags` 参数可只重建指定入站
- `main.go`：控制接口新增 `/users`、`/users/add`、`/users/remove`、`/users/ss-update`，返回重建耗时
- 修崩溃：`box.New` 把服务注册进 context 的服务注册表，必须自己先建好注册表和 pause 管理器再传进去，否则运行时 `InboundManager.Create` 空指针
- 测试脚本 `v4.py`（放在 VPS 的 run 目录）：按协议逐个测，每 2 秒采样计数增量

## 结果

- TCP 类（VLESS、AnyTLS、Shadowsocks）：重建入站期间流量一秒不停，耗时 1 毫秒
- Hysteria2：重建后在传会话全部归零且不自动恢复，但新连接立即可用
- Shadowsocks：`UpdateUsers` 可热更新用户，0 毫秒、不重建、不影响已有连接；`managed: true` 反而不能配静态用户
