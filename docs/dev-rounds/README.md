# 开发轮次记录

每一轮开发写一条记录：这一轮要做什么、做了什么、结果如何。和调试记录（[debug-runs](../debug-runs/README.md)）分开：一轮开发可能包含多次调试，互相链接。

本文件是规则，属于 main 分支。记录按分支放在子目录里：`main/`、`panel/`、`agent/`，每个子目录有自己的 `index.md`，只在对应分支上修改（见 [git-workflow.md](../git-workflow.md)）。

## 什么算一轮

- 一个明确的目标、一段连续的工作，通常是一个会话，或 ExecPlan 里的一步
- 以提交推送结束；目标没做完也要结束这一轮并如实记录。轮中也要及时推送
- 不算一轮：在 main 上只是把已有结论同步进设计文档、修正文档错误。提交信息写清楚改了什么即可，不写记录、不重写状态

## 规则

- **编号**：round-id 为 `D<年月日>-<分支>-<两位序号>`，例如 `D20260918-agent-01`；同一分支同一天从 01 开始
- **文件**：`docs/dev-rounds/<分支>/<round-id>-<简短英文标识>.md`；索引是 `docs/dev-rounds/<分支>/index.md`
- **时机**：开始时写「目的」；结束时补「做了什么」「结果」「遗留问题」「下一轮」
- **篇幅**：单篇不超过 60 行。不贴代码、diff 和日志，写文件路径、提交号和改动意图；设计结论写进 main 分支的设计文档，这里只链接
- **摘要**：标题下第一段是 1–3 行的摘要，只读摘要就能知道这一轮干了什么、结果如何
- **收尾**（每轮结束都要做）：
  1. 写完本轮记录，更新本分支的索引
  2. 整篇重写 `docs/status/<分支>.md`
  3. 用中文提交并推送

## 索引格式

每个分支的 `index.md`：

````markdown
# <分支> 分支的开发轮次

| round-id | 日期 | 标题 | 状态 | 摘要 |
| --- | --- | --- | --- | --- |
````

## 归档

- 每个索引只保留最近 30 条
- 更早的记录移到 `<分支>/archive/<年-月>/`，并在 `<分支>/archive/<年-月>.md` 写一篇不超过 30 行的当月总结；索引末尾链接到各月总结
