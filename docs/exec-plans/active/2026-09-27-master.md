## 目标与背景

主控是整个系统的中心：管理员在面板上管理服务器、节点、落地出口、套餐和用户；主控把每台服务器的期望状态推给 Agent，收 Agent 的流量上报算用量、按规则停用；朋友用订阅链接拿到各自客户端能用的配置。Agent 在 agent 分支，M1–M4 已完成（见 agent 分支的计划）。

做完后：一台有域名的机器运行 `op-master`，打开面板完成初始化，添加服务器（复制安装命令到节点服务器执行），建节点、套餐、用户，把订阅链接发给朋友即可使用；超额、到期自动停用，续期、清零后自动恢复。

## 意外发现

- 发现：axum 0.8 只给自带的 TcpListener 实现了取对端地址（ConnectInfo），自定义的 HTTPS 监听器取不到
  证据：`axum-0.8.9/src/extract/connect_info.rs` 只有 `IncomingStream<TcpListener>` 和 `TapIo` 的实现；给外部类型实现外部 trait 又违反孤儿规则
  影响：定义本地类型 `app::PeerAddr`，两种监听器各实现一次
- 发现：rustls-pemfile 已停止维护（有「不再维护」的安全公告）
  证据：crates.io 上最后一版是 2024 年；rustls-pki-types 1.x 自带 PEM 解析（`PemObject`）
  影响：改用 `rustls::pki_types::pem::PemObject`，去掉这个依赖
- 发现：cargo-deny 对我们自己这个不发布的 crate 报「没有许可证」
  证据：PR #9 第一次 CI 的 cargo-deny 结果
  影响：`deny.toml` 加 `[licenses.private] ignore = true`
- 发现：端到端测试里清零本周期后立即下载会失败：数据库已恢复，但新状态还要合并 3 秒才推给 Agent
  证据：R20260927-panel-01 的 e2e-1
  影响：是测试脚本的时序问题，产品行为符合设计；脚本改为等 Agent 应用后再测

## 决策记录

- 决策：SQL 用 sqlx 的运行时查询（`query` / `query_as` + `FromRow`），不用编译期检查的 `query!` 宏
  理由：宏要在编译时连数据库，或者提交用 `cargo sqlx prepare` 生成的离线数据；编译只在 VPS 和 CI 上做，每改一次 SQL 都要在 VPS 上重新生成再拷回开发电脑，太绕。表不多，SQL 错误靠集成测试覆盖
  日期：2026-09-27
- 决策：不生成 OpenAPI，前端的 API 类型手写在 `web/src/api/types.ts`，和主控 `src/api/` 里的请求、响应结构一一对应
  理由：utoipa 要给每个处理函数和结构体加注解，还要跑主控才能导出描述文件，接口只有几十个，手写一份类型更简单。改接口时两边一起改
  日期：2026-09-27
- 决策：YAML 用 `yaml-rust2`（MIT / Apache-2.0，2026 年还在维护）
  理由：serde_yaml 已停止维护，几个分支（serde_yaml_ng、serde_norway）也停在 2024 年；订阅模板只需要读成通用的树、插入节点、再输出，不需要 serde
  日期：2026-09-27
- 决策：证书用 `instant-acme`（ACME 协议）+ `rcgen`（CSR、自签证书），Cloudflare DNS 记录用 reqwest 直接调 REST API
  理由：都是 MIT / Apache，纯 Rust；DNS 服务商只有 Cloudflare 一家，不值得引入通用的 DNS 库
  日期：2026-09-27
- 决策：依赖选 API 稳定、用得最广的大版本（sqlx 0.8、reqwest 0.12、rand 0.8、rcgen 0.13、instant-acme 0.7 等），不追最新
  理由：写代码时照着本机下载的依赖源码核对 API，版本越常见越不容易出错；以后统一升级
  日期：2026-09-27
- 决策：TLS 用 rustls（ring），不用 aws-lc
  理由：aws-lc 要 cmake 和更多 C 编译依赖，交叉编译静态单文件更麻烦
  日期：2026-09-27
- 决策：主控默认监听 HTTPS（证书来自数据库；还没有正式证书时用启动时生成的临时自签证书），另外可以加一个明文 HTTP 监听，给反向代理和本机测试用
  理由：「主控必须有域名和正规证书」是正式部署的要求；测试 VPS 没有域名，Agent 只允许对本机回环地址用 http://（agent 分支 M4）
  日期：2026-09-27

- 决策：网卡计数第一次见到（或换了网卡）时只记为起点，不入账；服务器重启过（boot_id 变了）时增量 = 本次
  理由：第一次见到时的累计是开机以来的全部流量，记成今天的会让当天的整机流量虚高；database.md 只写了 boot_id 变了的情况
  日期：2026-09-27
- 决策：收到有用户流量的上报时，把全部用户的停用原因都重算一遍（不只看这次有流量的人）
  理由：用户只有几十个，一次重算很便宜；和每分钟的检查共用一个函数，规则只写一处
  日期：2026-09-27
- 决策：Agent 连上时这台服务器的期望状态还没算过（刚创建），当场重算一次再推
  理由：不用等 3 秒的合并窗口，新服务器装好 Agent 就能马上拿到配置
  日期：2026-09-27

## 实施方案

主控是一个进程（`master/src/`）：

| 模块 | 内容 |
| --- | --- |
| `main.rs`、`config.rs` | 命令行参数（数据目录、监听地址）、日志、启动各部分 |
| `db/` | 连接池（WAL、外键）、迁移、各表的读写 |
| `api/` | axum 路由和处理函数，一个资源一个文件；错误统一映射成 `{code, message}` |
| `agent/` | WebSocket 网关：认证、连接表、收发、请求等待表 |
| `state/` | 从数据库现算期望状态、哈希、升版本、合并推送 |
| `traffic/` | 流量上报入账、停用规则、每月重置、到期 |
| `subscription/` | 格式识别、各格式输出、模板和翻译 |
| `acme/` | 自签证书、ACME 申请和续期、主控证书热替换 |
| `jobs/` | 每分钟的检查任务、证书续期、远程模板拉取 |
| `web.rs` | 嵌入的前端（rust-embed），找不到的路径回 `index.html` |

- 数据目录默认 `/var/lib/op-master/`：`op-master.db`（SQLite）
- 共享状态 `AppState`：数据库连接池、Agent 连接表、期望状态推送器、设置缓存
- 期望状态：任何配置变更或停用状态变化后调用「标记需要重算」；推送器 3 秒内的多次标记合并成一次：重算所有服务器，哈希变了才升版本，推给在线的 Agent
- 订阅模板翻译只支持这些（`subscription.md`「待讨论」在此定下）：
  - 代理组：`select`、`url-test`、`fallback`、`load-balance`；`filter` 在服务端展开成具体节点，其他格式不用支持它
  - 规则：`DOMAIN`、`DOMAIN-SUFFIX`、`DOMAIN-KEYWORD`、`IP-CIDR`、`IP-CIDR6`、`GEOIP`、`MATCH`；`RULE-SET` 只翻译 `behavior: classical` 且 `format: text` 的远程规则集（各客户端都能直接用同一个地址）
  - 其他（`.mrs` 规则集、`domain` / `ipcidr` 规则集、`PROCESS-NAME`、`AND` / `OR` 等逻辑规则、`dns` 段、`sniffer` 等）：Mihomo 原样保留；其他格式丢掉并写进兼容性报告
  - 远程模板默认每 24 小时拉取一次，失败保留上一份
- 版本号：编译时环境变量 `OP_VERSION`，没有时为 `dev`
